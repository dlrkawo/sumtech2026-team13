# 목소리 인식 비교 일지

작성일: 2026-10-30

## 왜 했나

목소리로 묻기를 지금 FE처럼 브라우저 음성 인식으로 둘지, 서버에서 AI Gateway 음성 인식으로 바꿀지 정하려고 같은 말을 두 방식으로 받아 비교했습니다. 서버 쪽 API(`POST /api/voice-guides`, `google/gemini-3.5-transcribe`)는 #42로 이미 `main`에 있고, FE는 아직 부르지 않습니다.

- A: 브라우저 음성 인식(`SpeechRecognition`, ko-KR). 지금 FE의 `useSpeechInput`과 같은 방식입니다.
- B: `MediaRecorder` 녹음 → AI Gateway 음성 인식(`google/gemini-3.5-transcribe`). `/api/voice-guides`와 같은 요청 모양입니다.

## 어떻게 했나

- 이 폴더의 로컬 서버가 비교 페이지를 보여 주고, 녹음 파일을 Gateway로 대신 보냅니다. 키는 저장소 루트 `.env`에서 읽고 브라우저에는 넘기지 않습니다.
- 버튼 하나로 A와 B를 동시에 시작하고, 말을 멈춘 시각부터 각 결과가 나올 때까지의 시간을 쟀습니다.
- 환경: Windows PC, 엣지 156, 노트북 마이크, 녹음 형식 `audio/webm;codecs=opus`. 한 사람이 10번 말했습니다.
- 시도마다 결과를 `results.jsonl`에 한 줄씩 남겼습니다. 녹음 파일은 저장하지 않았습니다.
- 몇 번은 페이지의 정답 칸을 바꾸지 않고 말해서, 아래 표의 "말한 문장"은 실제로 말한 내용 기준으로 적었습니다.

## 틀리는 방식의 차이

- A는 틀려도 소리 나는 대로 틀립니다("정부 집사", "택배 좋아하는"). 이상한 문장이 되어 사용자가 알아채기 쉽습니다.
- B는 말하지 않은 그럴듯한 다른 말로 바꿀 때가 있습니다(8번 "정부24·주민등록등본" → "종부세·주택임대등록본"). 멀쩡한 문장처럼 보여서 틀린 걸 알아채기 어렵고, 그대로 안내 AI에 들어가면 엉뚱한 안내로 이어질 수 있습니다.

## 결론

- B가 숫자·금액·고유명사에서 대체로 더 정확하지만, 결과가 매번 4~5초 늦고 호출마다 팀 AI 예산을 씁니다. 그 뒤에 화면 안내 AI 호출(수 초)이 이어지므로 "말하고 → 안내"까지 기다리는 시간이 꽤 길어집니다.
- 1명·10문장·한 브라우저 결과라 일반화하기에는 적습니다.
- 그래서 지금 바로 바꾸지 않고, 다음 중에서 FE 담당과 정하기로 했습니다.
  1. 지금 방식(브라우저 음성 인식) 유지
  2. 어느 방식이든 알아들은 문장을 입력칸에 먼저 보여 주고 고칠 수 있게 하기
  3. 브라우저 음성 인식이 안 될 때(지원하지 않는 브라우저 등)만 B 쓰기
- 이 일지와 비교 페이지는 기록용 PR에 남기고 PR은 머지하지 않고 닫았습니다.

## 다시 돌려 보기

저장소 루트 `.env`에 `AI_GATEWAY_API_KEY`를 넣고 이 폴더의 `server.js`를 Node로 실행한 뒤, 크롬이나 엣지로 `http://localhost:4180`을 엽니다. 위쪽 목록에서 `elevenlabs/scribe-v2`, `openai/whisper-1`로 바꿔 비교할 수도 있습니다(이번에는 `google/gemini-3.5-transcribe`만 비교함). 호출마다 팀 AI 예산을 씁니다.

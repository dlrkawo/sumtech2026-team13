# 탭 공유 실험 일지

작성일: 2026-10-29

## 왜 했나

`docs/scenarios.yaml` 첫 초안의 S2~S8은 사용자가 대상 웹 탭을 공유(`getDisplayMedia`)하는 것에서 시작합니다. 키트 E2E는 Playwright로 실제 앱을 조작하므로, 브라우저의 공유 선택 창을 E2E에서 넘길 수 있는지 기능 개발 전에 확인했습니다.

확인 전 알고 있던 제약은 다음과 같습니다.

- 주최 측 실행은 우리 `e2e/playwright.config.ts`를 쓰지 않고 자체 설정으로 돕니다. 여기에만 둔 브라우저 실행 옵션은 적용되지 않습니다.
- spec에서 `page.route`·`addInitScript` 등으로 가짜 응답이나 상태를 만들 수 없습니다.

## 어떻게 했나

- Playwright 1.63.0(키트 `e2e/`와 같은 버전), Chromium, 화면 크기 1440×900
- 대상 탭으로 "모의 신청 페이지"(왼쪽 위 빨간 상자, '신청이 완료되었습니다' 문구)를 먼저 열어 두고, 서비스 탭에서 '화면 공유'를 누른 뒤 공유된 화면의 한 프레임에서 빨간 상자 자리 픽셀을 읽어 무엇이 찍혔는지 확인했습니다.
- 브라우저 실행 옵션을 바꿔 가며 같은 동작을 반복했고, 이어서 iframe을 쓰는 방법도 확인했습니다.

## 결과 1: 탭 공유

| 조건 | 결과 |
| --- | --- |
| 키트 기본 조건(실행 옵션 없음) | 누르자마자 `NotSupportedError` |
| 탭 제목으로 자동 선택 옵션 | `NotSupportedError` |
| 창 이름으로 자동 선택 옵션 | `NotSupportedError` |
| 권한 창 자동 수락 옵션 | 공유는 되지만 화면 전체가 잡힘. 대상 탭이 아니라 앞에 있는 서비스 화면이 찍힘 |
| 새 headless 모드 + 탭 제목 자동 선택 | 응답 없이 멈춤 |
| 새 headless 모드 + 권한 창 자동 수락 | 화면 전체가 잡힘. 대상 탭 아님 |
| 브라우저 창 표시(headed) + 탭 제목 자동 선택 | 응답 없이 멈춤 |

- 키트 기본 조건에서는 화면 공유가 아예 동작하지 않습니다. 실행 옵션을 줘도 특정 탭을 골라 공유하는 방법은 찾지 못했습니다.
- 주최 측 실행의 정확한 브라우저 모드는 확인하지 못했습니다(주최 측 문의 필요).

## 결과 2: iframe

| 방법 | 결과 |
| --- | --- |
| iframe이 들어 있는 현재 탭 공유(`preferCurrentTab`) | `NotSupportedError` |
| iframe 안에서 화면 공유 호출(`allow="display-capture"`) | `NotSupportedError` |
| 같은 출처 iframe을 `html2canvas`로 캡처 | 권한 요청 없이 캡처됨. 빨간 상자 픽셀 `[255,0,0]` 확인 |
| 외부 사이트를 iframe에 표시 | 네이버·유튜브는 사이트가 거부. 카카오뱅크·심평원·정부24·쿠팡은 무언가 표시되지만 부모 페이지에서 내용을 읽을 수 없음 |

- 화면 공유는 어디서 호출해도 같은 결과입니다.
- iframe 캡처는 우리 앱 안의 페이지에만 쓸 수 있습니다. 외부 사이트는 다른 출처라 캡처할 수 없습니다.

## 결과 3: 음성

음성으로 질문하기와 읽어주기를 시나리오에 넣을 수 있는지 같은 방식으로 확인했습니다. 비교용으로 가짜 마이크 장치 실행 옵션을 준 조건도 함께 돌렸습니다(주최 측 실행에는 적용되지 않음).

| 기능 | 키트 기본 조건 | 가짜 마이크 옵션 |
| --- | --- | --- |
| 마이크 녹음 | `NotSupportedError`. spec에서 마이크 권한을 줘도 같음 | 녹음됨(가짜 장치 소리) |
| 브라우저 음성 인식(Web Speech API) | 8초 동안 아무 이벤트 없음 | 같음 |
| 음성 파일 올리기 | 업로드 후 브라우저에서 해석까지 됨(0.5초 wav) | 같음 |
| 읽어주기(TTS) | 시작 이벤트는 오지만 설치된 음성이 0개 | 같음 |

- 마이크는 화면 공유와 같은 이유로 키트 기본 조건에서 막혀 있습니다. 주최 측의 목업 허락은 화면 공유에 대한 것이라, 마이크를 시나리오에 넣으려면 따로 허락이 필요합니다.
- 브라우저 음성 인식은 가짜 마이크를 줘도 반응이 없어 E2E에 쓸 수 없습니다.
- 음성 파일 올리기는 화면 사진 올리기와 같은 방식으로 쓸 수 있습니다. 실제 녹음을 AI(Gemini 계열)로 보내 결과를 받는 것은 아직 확인하지 않았습니다.
- 읽어주기는 소리가 실제로 나는지는 확인할 수 없고, '읽는 중' 같은 화면 상태로만 확인할 수 있습니다. 실제 사용자 PC의 한국어 음성 여부는 확인하지 않았습니다.

## 결론

- 시나리오 초안대로 탭 공유로 시작하는 흐름(S2~S5, S7, S8)은 주최 측 E2E에서 실패할 가능성이 큽니다. S6(공유 취소)는 결과 문구는 맞출 수 있지만 '취소를 누른다' 단계를 화면 조작으로 옮길 수 없습니다.
- '화면 공유' 버튼 뒤에 가짜 화면을 몰래 넣는 방식은 키트의 가짜 상태 금지 규칙에 걸리고 실제 사용자에게도 엉뚱한 안내를 줄 수 있어 쓰지 않습니다.
- 대신 화면에 드러나는 별도 기능으로 E2E 경로를 만듭니다.
  - 연습 모드: 우리 앱 안의 모의 페이지를 iframe으로 띄우고, 사용자가 그 안에서 직접 누른 뒤 '현재 화면 분석'을 누르면 iframe을 캡처해 실제 AI로 분석합니다. S4의 직접 선택까지 실제 조작으로 확인할 수 있고, 완료 문구가 있는/없는 페이지로 S5·S8을 확인합니다.
  - 캡처 이미지 올리기: 사용자가 자기 화면 캡처를 올립니다. 업로드 이미지는 `e2e/fixtures/`에 둡니다.
- 실제 외부 사이트는 기존처럼 탭 공유로 안내합니다.
- 음성도 같은 구조로 갑니다. 실제 사용은 마이크 녹음으로 하고, 시나리오에서는 '음성 파일 올리기'(`e2e/fixtures/`의 녹음 파일)로 같은 분석 흐름을 확인합니다.

## 다시 돌려 보기

이 폴더에서 의존성과 Chromium을 설치한 뒤 Playwright 테스트를 실행하면 위 표의 결과가 콘솔에 출력됩니다. 프로젝트(실행 조건) 목록은 `playwright.config.js`, 확인 동작은 `tests/`에 있습니다.
